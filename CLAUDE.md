# CLAUDE.md

Guidance for AI coding agents (Claude Code and others) working in this repo. Humans: see CONTRIBUTING.md.

## What this is

An open-source AI ordering agent for quick-service restaurants. Customers say or type what they want; the agent builds the cart from the menu, asks only for missing choices and the owner's order questions, and the order goes to the kitchen (POS).

## Commands

```sh
pnpm install
pnpm dev                          # API on :8787 and web on :3000
pnpm test                         # all unit tests (no API key needed)
pnpm typecheck
pnpm menu                         # print the demo menu
pnpm --filter @foa/agent eval     # grade the real LLM on evals/*.json for both demo menus (needs a key in .env)
```

## Layout

- `packages/core`: menu schema, cart engine, menu search, owner questions, shared API types (`src/api.ts`), demo menu.
- `packages/agent`: LLM agent. `actions.ts` (pure order actions), `tools.ts` (AI SDK tools wrapping them), `prompt.ts`, `run.ts`, `model.ts` (provider choice).
- `apps/server`: Hono API under `/api`, PGlite locally, Supabase (or any Postgres) via `DATABASE_URL` in production; tables keep row-level security on, POS adapter (`pos.ts`; Square in `src/square/`: catalog ↔ menu, orders, payments), speech provider (`speech.ts`, ElevenLabs).
- `apps/web`: Next.js pages: ordering link, kiosk, kitchen screen, owner settings, embed script. Customer screens are agent-only (no tap menu): `components/agent/` holds the orb stage, talk/type bar and live order card; `lib/use-agent-input.ts` joins mic, agent and spoken replies into one phase. Replies stream from `/message/stream` and are spoken a sentence at a time through Web Audio (`lib/speech.ts`), with the text held until the voice starts.
- `evals/demo-orders.json` (burger) and `evals/tea-orders.json` (bubble tea): sample orders and multi-turn conversations with expected carts; used by unit tests and the LLM eval. `DEMO_MENU` picks which menu the server serves.

## Rules that must not break

- The model changes the order only through tools; every tool call is validated by the cart engine against the menu.
- Only what the customer said exactly (a menu name or alias, `packages/core/src/match.ts`) goes straight into the order. Misheard speech is matched by sound (`packages/core/src/phonetic.ts`) only to suggest the right item; sound-alikes are always confirmed. Anything else is held as a guess until the customer says yes in a later turn (`confirm_changes`); tools must keep passing the customer's own words in `said`.
- Prices come only from menu data, and the server re-prices and re-validates the cart at checkout.
- Allergen information is never generated by the model. Only show what the menu lists, with "please confirm with staff".
- Required owner questions block checkout.
- What to ask comes from menu data, not the prompt: required groups without a default are asked (all missing ones in one question), `offer: true` groups and `mealItemId` meals are offered once, and option `aliases` count as exact words.
- Keep `@foa/core` free of server and UI dependencies; keep the agent provider-agnostic (Anthropic, OpenAI, OpenRouter).
- Customer screens stay agent-only: no browsable menu. Taps are for fixing order lines, the agent's choice buttons and owner questions.
- The kiosk layout is portrait first (monitor turned 90°, 1080×1920); keep touch targets large.
- The demo menus (Patty & Co., Bramble Tea) are fictional. Don't add real brand names or trademarks.

## Conventions

- TypeScript strict, ESM, Zod for anything crossing a boundary. Money is integer cents.
- Add or update tests with every behaviour change; add eval cases for new ordering behaviour.
- Never commit `.env` or anything in `.data/`.
- Square: test only against the Sandbox; `square:seed` refuses production. A POS failure must never lose an order (`syncPos` saves the error on it).
